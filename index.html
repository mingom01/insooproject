01

1. 문제의 구조

문제 상황과 선정 이유

학생은 여러 과목의 과제와 수행평가를 동시에 관리해야 한다. 일정이 공책, 메시지, 기억 등에 흩어져 있으면 마감일을 놓치거나 급하지 않은 과제부터 처리할 수 있다. 이 프로젝트에서는 이러한 일상생활의 불편을 해결하기 위해 마감일과 중요도를 기준으로 미완료 과제를 정렬하는 프로그램을 제작한다. 실제로 어느 정도 불편이 있는지는 개발 전 간단한 면담과 사용 기록으로 확인한다.

사용자와 입력·처리·출력

  • 사용자: 여러 과목의 과제를 관리하는 중·고등학생.
  • 입력: 과제 이름, 마감일(YYYY-MM-DD), 중요도(1~5), 완료 여부(True/False).
  • 처리: 입력 검증 → 남은 날짜 계산 → 완료 과제 제외 → 마감일·중요도 순 정렬.
  • 출력: 먼저 확인할 과제 목록, 마감까지 남은 일수, 기한이 지난 과제, 중요도.

제한 조건과 기능 분해

Python 표준 라이브러리만 사용하고, 인터넷 연결이나 회원가입 없이 실행한다. 이름·연락처 등 개인정보는 수집하지 않는다. 최초 버전은 코드의 리스트에 과제를 작성하는 콘솔 시제품으로 개발하며, 입력 메뉴·파일 저장·알림은 이후 개선 기능으로 구분한다.

기능은 과제 자료 입력, 입력 오류 확인, 날짜 계산, 우선순위 정렬, 결과 출력으로 나눈다. 제출이 막힌 과제는 직접 확인해야 하며, 프로그램이 제출 가능 여부나 최적 학습 일정을 판단하지는 않는다.

02

2. 알고리즘 선택

자료구조

과제 여러 개는 리스트에 저장하고, 각 과제의 이름·마감일·중요도·완료 여부는 딕셔너리로 관리한다. 자료가 늘어나도 같은 구조로 추가하기 쉽고, 필드 이름으로 각 값을 구분할 수 있기 때문이다.

후보 비교와 선택 근거

  • 입력 순서 유지: 구현은 가장 쉽지만 마감이 가까운 과제가 뒤에 남을 수 있다.
  • 중요도만 기준으로 정렬: 중요한 과제를 먼저 볼 수 있지만 급한 과제의 마감을 놓칠 수 있다.
  • 마감일 우선, 같은 날은 중요도순 정렬: 긴급성과 중요도를 함께 반영할 수 있어 선택한다.

최종 규칙

① 완료 과제는 제외한다. ② 마감일이 빠른 순으로 정렬한다. 기한이 지난 과제도 목록에서 숨기지 않고 먼저 표시한다. ③ 같은 마감일이면 중요도가 높은 과제를 먼저 배치한다. ④ 두 조건이 모두 같으면 과제 이름의 문자열 순서로 정렬하여 결과를 일정하게 유지한다.

이는 과제 확인 순서를 제안하는 단순한 규칙 기반 알고리즘이다. 과제 소요 시간과 선후 관계까지 고려한 최적 일정 계산은 아니다.

03

3. 코드 구현

구현 범위

Python의 datetime 모듈로 날짜를 처리한다. prioritize_tasks()는 입력 자료를 검증하고 미완료 과제의 우선순위 목록을 반환한다. 실행 부분에서는 가상 과제를 이용하여 결과를 출력하고 ValueError가 발생하면 입력 오류를 안내한다. 완료 여부를 생략하면 미완료(False)로 처리한다.

최초 버전에서는 과제 리스트를 직접 수정하여 입력한다. 실제 날짜 기준으로 사용하려면 prioritize_tasks(tasks)로 호출하며, 아래 시연에서는 재현을 위해 기준일을 2026-11-04로 고정한다.

핵심 코드 및 실행 예시

PYTHON · 실행 가능한 예시 코드
from datetime import date


def prioritize_tasks(tasks, today=None):
    """미완료 과제를 마감일, 중요도, 이름 순서로 정렬한다."""
    if not isinstance(tasks, list):
        raise ValueError("과제 자료는 리스트여야 합니다.")
    if today is None:
        today = date.today()
    result = []
    for task in tasks:
        if not isinstance(task, dict):
            raise ValueError("각 과제는 딕셔너리여야 합니다.")
        name = task.get("name")
        due = task.get("due")
        importance = task.get("importance")
        done = task.get("done", False)
        if not isinstance(name, str) or not name.strip():
            raise ValueError("과제 이름을 입력하세요.")
        if not isinstance(due, str):
            raise ValueError("마감일은 YYYY-MM-DD 문자열로 입력하세요.")
        try:
            deadline = date.fromisoformat(due)
        except ValueError:
            raise ValueError("유효한 날짜를 입력하세요.") from None
        if deadline.isoformat() != due:
            raise ValueError("마감일은 YYYY-MM-DD 형식이어야 합니다.")
        if type(importance) is not int or not 1 <= importance <= 5:
            raise ValueError("중요도는 1~5 사이의 정수여야 합니다.")
        if type(done) is not bool:
            raise ValueError("완료 여부는 True 또는 False여야 합니다.")
        if not done:
            result.append({"name": name.strip(),
                           "days": (deadline - today).days,
                           "importance": importance})
    return sorted(result,
                  key=lambda t: (t["days"], -t["importance"], t["name"]))


if __name__ == "__main__":
    # 재현 가능한 시연을 위한 가상 과제와 고정 기준일이다.
    tasks = [
        {"name": "수학 문제 풀이", "due": "2026-11-06", "importance": 4},
        {"name": "영어 단어 학습", "due": "2026-11-05", "importance": 3},
        {"name": "정보과학 프로젝트", "due": "2026-11-05", "importance": 5},
        {"name": "국어 독서 기록", "due": "2026-11-03", "importance": 2},
        {"name": "완료한 과제", "due": "2026-11-04", "importance": 5,
         "done": True},
    ]
    try:
        result = prioritize_tasks(tasks, today=date(2026, 11, 4))
        if not result:
            print("남은 과제가 없습니다.")
        for task in result:
            days = task["days"]
            label = (f"기한 {abs(days)}일 지남" if days < 0 else
                     "오늘 마감" if days == 0 else f"마감까지 {days}일")
            print(f'{task["name"]} | {label} | 중요도 {task["importance"]}')
    except ValueError as error:
        print(f"입력 오류: {error}")

정보과학 프로젝트 | 마감까지 1일 | 중요도 5

위 결과는 제공한 예시 코드를 실행하여 확인했다. 학생의 실제 과제나 성과를 의미하지 않는다.

04

4. 효율성 분석

전체 과제 수를 n, 미완료 과제 수를 m이라고 할 때 입력 검증과 날짜 계산은 O(n), 정렬은 O(m log m)이다. 따라서 전체 시간 복잡도는 O(n + m log m)이며, 최악의 경우 O(n log n)이다. 결과 리스트와 정렬에 필요한 추가 공간은 O(m), 최악의 경우 O(n)이다. 이 분석은 과제명 등 문자열 길이를 제한적인 크기로 보는 일반적인 가정에 따른 것이다.

추후 가상 자료 10개·100개·1,000개를 만들고 time.perf_counter()로 함수 실행 시간을 크기별 100회 측정한다. 자료 생성과 화면 출력 시간은 제외하고 평균 실행 시간을 비교한다. 아직 이 성능 실험은 수행하지 않았으므로 측정값은 기재하지 않는다.

5. 프로젝트 적용

시연 계획

과제명·마감일·중요도가 다른 가상 과제를 입력하고 출력 순서가 규칙과 일치하는지 확인한다. 이후 시범 사용자는 자신의 과제를 입력하고, 과제를 마치면 done을 True로 바꾸어 목록에서 제외되는지 확인한다. 현재 버전에는 자동 알림과 저장 기능이 없다는 점을 안내한다.

2주간 활동 일정

  • 1~2일: 학생 3명 이상에게 일정 관리의 불편을 질문하고 필요한 기능을 정리한다. 이때 면담은 계획이며 아직 수행하지 않았다.
  • 3~4일: 입력 항목, 리스트·딕셔너리 구조, 정렬 규칙과 가상 자료를 설계한다.
  • 5~6일: 날짜 계산·정렬·출력 기능을 구현하고 코드 실행 과정을 설명한다.
  • 7일: 정상·경계·예외 입력을 시험하고 발견한 오류를 수정한다.
  • 8~12일: 본인과 학생 3명 이상의 자발적인 시범 사용을 진행한다. 개발·점검 시간은 하루 약 30분, 사용자의 일일 입력·확인은 약 5분을 목표로 한다.
  • 13일: 누락 건수, 목록 확인 시간, 사용 의견을 정리한다.
  • 14일: 개선 사항을 반영하고 최종 보고서·시연 자료를 완성한다.

8. 개선

1순위: 과제를 코드 수정 없이 등록·수정·완료 처리할 수 있는 입력 메뉴를 만든다. 잘못 입력한 항목을 다시 안내하도록 한다.

2순위: JSON 파일 저장·불러오기를 추가한다. 파일 없음·손상에 대한 예외 처리는 구현 후 별도 테스트한다.

3순위: 기한이 지난 과제를 별도 영역으로 표시하고, 제출 불가·취소된 과제를 보관 처리할 수 있도록 한다.

확장 기능: tkinter 화면, 예상 소요 시간, 과목별 필터, 마감 알림을 검토한다. 현재 코드에 없는 기능은 구현된 것처럼 설명하지 않는다.

개선 검증: 기존 16개 테스트가 계속 통과하는지 재검사하고, 새 기능별 테스트와 사용 의견을 추가한다. 개선 전후의 입력 시간과 실수 횟수를 동일한 조건으로 비교한다.

최종 성찰 — 활동 후 작성 방향

문제를 입력·처리·출력으로 나누고, 리스트·딕셔너리와 정렬을 활용한 이유를 설명한다. 예상과 실제 결과가 달랐던 부분, 직접 수정한 오류, 사용자의 피드백으로 달라진 점은 실제 활동 이후 작성한다. 아직 수행하지 않은 활동을 경험한 것처럼 적지 않는다.
